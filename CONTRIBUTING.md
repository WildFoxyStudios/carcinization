# Contributing to Carcinization

**Thank you for your interest in contributing to Carcinization!**

This document will outline the basics of where to start if you wish to contribute to the project. There are many ways to help us out and and we appreciate all of them. We look forward to **your contribution!**

**Please read this document until the end to not waste your and our time with unnecessary questions**

## Code Of Conduct

## Contribution Terms

When making a contribution you agree to the following terms:

- I understand these changes in full and will be able to respond to review comments.
- I have read the [Developer Certificate of Origin](https://developercertificate.org/) and certify my contribution under its conditions.

## AI Policy

Carcinization OS does not accept contributions generated by LLMs ([Large Language Models](https://en.wikipedia.org/wiki/Large_language_model)), sometimes also referred to as "AI". This policy is not open to discussion, any content submitted that is clearly labelled as LLM-generated (including issues, merge requests, and merge request descriptions) will be immediately closed, and any attempt to bypass this policy will result in a ban from the project.

(We recommend that you leave the "Join Requests" room after your entry on Carcinization space)

If you want to have a big discussion in our rooms, you should use a Element thread, it's more organized and easy to keep track if more discussions happen on the same room.

### [Discord](https://discord.gg/JfggvrHGDY)

We have a Discord server as an alternative for Matrix, open the #join-requests channel and send a message requesting to be a member (the purpose of this is to avoid spam and bots)

The Matrix messages are sent to Discord and vice-versa using a bot, but sometimes some Discord messages aren't sent to Matrix (if this happens to you join in our Matrix space above)

## [GitLab](https://gitlab.redox-os.org/redox-os/redox)

A slightly more formal way of communication with fellow Carcinization developers, but a little less quick and convenient like the chat. Submit an issue when you run into problems compiling or testing. Issues can also be used if you would like to discuss a certain topic: be it features, code style, code inconsistencies, minor changes and fixes, etc.

If you want to create an account, read the [Signing in to GitLab](https://doc.redox-os.org/book/signing-in-to-gitlab.html) page.

Once you create an issue don't forget to post the link on the Dev or Support rooms of the chat, because the GitLab email notifications have distractions (service messages or spam) and most developers don't left their GitLab pages open to receive desktop notifications from the web browser (which require a custom setting to receive issue notifications).

By doing this you help us to pay attention to your issues and avoid them to be accidentally forgotten.

If you have ready MRs (merge requests) you must send the links in the [MRs](https://matrix.to/#/#redox-mrs:matrix.org) room. To join this room, you will need to request an invite in the [Join Requests](https://matrix.to/#/#redox-join:matrix.org) room.

By sending a message in the room, your MR will not be forgotten or accumulate conflicts.

## Notes

This section has important details to not waste your and our time with unnecessary questions.

- We don't accept Git pushs using SSH, to protect against AI scrappers and bots. You need to use [HTTPS with your PAT](https://doc.redox-os.org/book/signing-in-to-gitlab.html#setting-up-pat) in our GitLab server.
- For complete or advanced development you need the [Carcinization build system](https://doc.redox-os.org/book/podman-build.html) instead of Carcinizer.
- If you want to work on individual repositories without the Carcinization build system you need to use [Carcinizer](https://gitlab.redox-os.org/redox-os/redoxer) because our toolchain is not fully upstreamed yet.
- When creating a MR write a short title and explain your changes on description (if long enough to be necessary) in a easy way and what they fixed or/and improved, use a bullet item list if you did multiple changes that aren't explained in commit titles.
- If you want to contribute to `relibc`, read its [CONTRIBUTING.md](https://gitlab.redox-os.org/redox-os/relibc/-/blob/master/CONTRIBUTING.md) document before.

## Development Recommendations and Tips

- Copy-paste prevent and reduce typos
- Comment out configuration or code while testing is better than removal, to remember the testing conditions and prevent mistakes from forgotten logic
- Read the entire [Build System Reference](https://doc.redox-os.org/book/build-system-reference.html) and [Developer FAQ](https://doc.redox-os.org/book/developer-faq.html) pages
- Make sure your build system is up-to-date, read the [Update The Build System](https://doc.redox-os.org/book/build-system-reference.html#update-the-build-system) section if in doubt.
- If you want to make local changes in recipe sources it's recommended to disable the automatic recipe source update, read [this](https://doc.redox-os.org/book/configuration-settings.html#local-recipe-changes) section to learn how to this for one or multiple recipes and [this](https://doc.redox-os.org/book/configuration-settings.html#cookbook-offline-mode) section for all recipes.
- If you want to make changes to system components, drivers or CarcinizationFS, you need to manually update initfs, read [this](https://doc.redox-os.org/book/coding-and-building.html#how-to-update-initfs) section to learn how to do that.
- If some program can't build or work, something can be missing/hiding on [relibc](https://gitlab.redox-os.org/redox-os/relibc), like a POSIX/Linux function or bug.
- If you have some error on QEMU remember to test different settings or verify your operating system (Pop_OS!, Ubuntu, Debian and Fedora are the recommend Linux distributions to do testing/development for Carcinization).
- Remember to log all errors, you can use the following command as example:

```sh
your-command 2>&1 | tee file-name.log
```

- If a bug is random or hard to reproduce, disable KVM with the `make qemu kvm=no` command to see if it becomes more frequent
- If you have a problem that seems to not have a solution, do the following things:
  - Write down your thoughts to reduce cognitive load and better analyze the details, high complexity in mind space can make you forget parts of the logical construct, cause confusion and redundancy
  - Verify if basic functionality is working (if you are working on complex functionality)
  - Think on simple/stupid things that may not have a obvious breakage

Sometimes you are very confident on your method and forget obvious things (very common).

- If you want a quick review of your Merge Request, make it small.
- If your big Merge Request is taking too long to be reviewed and merged try to split it in small MRs. But make sure it don't break anything, if this method break your changes, don't shrink.

## Build System

To download the build system use the following commands:

(You need to have [curl](https://curl.se/) installed on your system)

```sh
curl -sf https://gitlab.redox-os.org/redox-os/redox/raw/master/podman_bootstrap.sh -o podman_bootstrap.sh
```

```sh
time bash -e podman_bootstrap.sh
```

To start the compilation of the default recipes run the command below:

```sh
make all
```

In case your operating system does not use SELinux, you must set the `USE_SELINUX` to `0` when calling `make all`, otherwise you might experience errors:

```sh
make all USE_SELINUX=0
```

You can find the build system organization and commands on the [Build System](https://doc.redox-os.org/book/build-system-reference.html) page.

### Debian source packages

A recipe can take its sources from a Debian source package instead of a plain
tarball. Point it at the `.dsc` file and the build system does the rest:

```toml
[source]
dsc = "https://deb.debian.org/debian/pool/main/h/hello/hello_2.10-3.dsc"

[build]
template = "custom"
script = """
DYNAMIC_STATIC_INIT
cookbook_configure
"""
```

The `.dsc` file and every tarball it references are downloaded and checked
against the SHA256 sums the `.dsc` carries, so a corrupted or substituted
download is rejected. The upstream tarball is then laid out in the source
directory, the Debian packaging tarball is unpacked over it, and the quilt
series of `debian/patches` is applied.

What comes out is an ordinary source tree, so the package is built with the
usual templates. Because the build goes through relibc and not glibc, the
resulting binaries run on Carcinization OS, which is the whole point: the same
upstream release, but linked against our C library.

A recipe may add patches of its own on top of the Debian ones, and may run a
script to prepare the sources:

```toml
[source]
dsc = "https://deb.debian.org/debian/pool/main/s/some/some_1.2-3.dsc"
patches = ["carcinization-relibc.patch"]
script = """
./autogen.sh
"""
```

Keep in mind that the Debian patches are written for a glibc system, so a
package that needs more work usually needs a patch of its own on top. The
`Build-Depends` of the source package are listed in `debian/control`; the ones
that are actually needed have to be repeated in the `dependencies` of the
recipe, because `debhelper` is not used.

`recipes/wip/deb-hello` is a working example.

### Debian packages on the guest

The `apt` frontends install `.deb` packages from a Debian mirror. Three
differences between Redox and a glibc system have to be worked around, and
they are worth knowing about before changing that code.

**`wget` never finishes.** The GNU `wget` port for Redox does not recognise
where the HTTP response body ends: it writes the response headers into the
output file and then waits forever for more data. `curl` handles the
response correctly, so it is the one the frontends use. `wget` is only
fallback for the systems where `curl` is not installed.

**`pkg` exits successfully when it fails.** `pkg install` reports a package
that its repository does not have with an error message, but still exits with
a success status. The frontends cannot use that status to find out whether a
request was satisfied, so they ask the repository with `pkg search` instead,
and take the packages it does not have from the Debian mirror.

**The filesystem has no file descriptor based metadata calls.** `redoxfs`
implements `fchown`, but not `fchmod` nor `futimens`, and it is the path
based `chmod` that works. The `tar` crate sets the permissions and the
modification times of the files it extracts with the descriptor based calls,
so unpacking a `.deb` with it fails. The extraction is done by hand instead:
the contents are written and the permissions are set on the path.

### Packages excluded by their license

Not every program can be shipped as a Carcinization OS package. A recipe
redistributes the upstream source, so it can only exist for software whose
license allows that. When it does not, the package is left out and a free
alternative is used instead.

`unrar` is the clearest example, and it used to have a recipe. The license of
RARLAB's unrar does not meet the Debian Free Software Guidelines, so Debian
removed it from `main` and ships it in the `non-free` archive instead, under
the source package `unrar-nonfree` and flagged as not free software. A
Carcinization OS package is part of the free system, so the recipe has been
removed.

The functionality is not lost. RAR archives are read with `bsdtar`, which comes
from `libarchive` and is under a permissive license:

```sh
bsdtar -x -f archive.rar
```

Other free alternatives exist as well, such as `unrar-free` and `p7zip-rar`.

Two things had to change for that:

- `podman/carcinization-base-containerfile` installs `libarchive-tools`, so
  that the build container has `bsdtar`.
- `recipes/wip/games/data/openjazz-shareware-data` unpacks its RAR archive
  with `bsdtar -x -f jazzdemo.rar` instead of `unrar x -u jazzdemo.rar`.

Before adding a recipe, check the license of the upstream sources. If it
forbids redistribution, or does not meet the Free Software Guidelines, do not
add the recipe: look for a free alternative that does the same job, as `bsdtar`
does here. If there is none, leave the package out rather than shipping it
with a license that does not permit it.
